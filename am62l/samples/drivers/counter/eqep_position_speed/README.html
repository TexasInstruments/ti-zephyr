EQEP Position and Speed Measurement

Overview

This sample demonstrates how to use the TI Enhanced Quadrature Encoder Pulse (EQEP) counter driver to measure the position and rotational speed of a quadrature incremental encoder.

It is fully self-contained: no physical encoder is required. A single TI EHRPWM instance (main_epwm0), running in symmetric (up-down counting) mode, generates both simulated quadrature phases from its two channels:

  • Channel 0 (A) uses the driver’s default action-qualifier behaviour: a 50%-duty output whose edges are tied to its own compare register, centered on the counter’s zero-crossing.

  • Channel 1 (B) is configured with the TI EHRPWM-specific TI_EHRPWM_USE_AQ_SET_ZRO_PRD flag (from include/zephyr/dt-bindings/pwm/ti_am3352_ehrpwm.h), which ties its edges to the shared ZERO/PERIOD events instead of its own compare register.

Because both channels share the same symmetric time base, the result is two 50%-duty square waves 90 degrees out of phase with each other - a quadrature pair generated entirely from one peripheral’s two channels, with no second PWM instance and no dead-band hardware involved. A GPIO is pulsed once per simulated revolution to simulate the index signal. These three signals must be jumper-wired back into the EQEP0 inputs (see Wiring below).

The quadrature decoder is configured for 4x counting (both edges of both the A and B channels). The position counter free-runs continuously rather than resetting each revolution: it starts at the reverse-direction wrap boundary and only wraps after the full 32-bit range, so consecutive index samples keep accumulating by CONFIG_APP_EQEP_LINES_PER_REV * 4 counts per revolution instead of restarting from zero.

The simulated A/B signals are generated by driving main_epwm0 at CONFIG_APP_EPWM_OUTPUT_FREQ_HZ, 50% duty, PWM_POLARITY_NORMAL on both channels (channel 1 additionally sets TI_EHRPWM_USE_AQ_SET_ZRO_PRD as described above).

The index pulse is derived from main_epwm0’s period interrupt (CONFIG_PWM_EVENT): the sample counts PWM periods and pulses the index GPIO for one period every CONFIG_APP_EQEP_LINES_PER_REV periods, i.e. once per simulated revolution.

Position and speed are reported by the EQEP’s own index-event hardware alarm (TI_EQEP_ALARM_CHAN_INDEX), not by a periodic timer: every time the index GPIO’s rising edge is latched by the decoder, the driver fires a callback with the position counter’s value at that exact instant, and the callback re-arms itself for the next revolution (EQEP alarms are one-shot). With this A/B phase relationship the simulated encoder counts down (counter-clockwise), so the reported position decreases every revolution; the speed calculation subtracts in that order (previous minus current) so the printed RPM comes out positive.

Requirements

This sample requires jumper wires between the simulated encoder signals and the EQEP0 inputs - no external encoder hardware is needed.

Wiring

On am62l_evm, jumper the following pins:

  • EHRPWM0_A (pin 18 of J2) -> EQEP0_A (pin 19 of J2)

  • EHRPWM0_B (pin 7 of J3) -> EQEP0_B (pin 14 of J2)

  • GPIO0_23 (pin 10 of J3) -> EQEP0_I (pin 15 of J2)

The EQEP0_S (strobe) input is unused by this sample and can be left unconnected.

Supported Boards

  • am62l_evm/am62l3/a53

Building and Running

west build -p always -b am62l_evm/am62l3/a53 samples/drivers/counter/eqep_position_speed

Use the generated tiboot3.bin and tispl.bin to run.

Configuration

  • CONFIG_APP_EQEP_LINES_PER_REV: number of simulated encoder lines per mechanical revolution (default 1000).

  • CONFIG_APP_EPWM_OUTPUT_FREQ_HZ: simulated encoder electrical frequency, i.e. the EHRPWM output frequency (default 5000).

With the defaults above, expected speed = CONFIG_APP_EPWM_OUTPUT_FREQ_HZ * 60 / CONFIG_APP_EQEP_LINES_PER_REV = 300 RPM, printed at startup for comparison against the reported speed.
