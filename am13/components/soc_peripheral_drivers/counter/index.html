Counter

EQEP Counter

Important

The ti,am3352-eqep driver controls the Enhanced Quadrature Encoder Pulse (EQEP) modules of the device. An EQEP module connects to a linear or rotary incremental encoder and reports position, direction and speed. Applications see it as a 32-bit counter of the encoder quadrature clock.

Features Supported

  • Counter API (<zephyr/drivers/counter.h>): counter_start(), counter_stop(), counter_get_value(), counter_get_top_value(), counter_set_top_value(), counter_set_channel_alarm(), counter_cancel_channel_alarm(), counter_get_pending_int(), counter_get_freq(), counter_is_counting_up() and the guard period calls

  • 32-bit position counter. The top value (maximum position, QPOSMAX) is 0xFFFFFFFF after init. The counter wraps to 0 above the top value and to the top value below 0. The top callback is called on every overflow and underflow.

  • Direction reported by the hardware: counting up when quadrature input A leads B (clockwise), down otherwise

  • Four counting modes, selected with ti_eqep_configure_decoder() (enum ti_eqep_src):

    • quadrature count: clock and direction decoded from A and B, four counts per line (both edges of both inputs)

    • direction count: A is the clock, B is the direction

    • up count and down count: fixed direction, the counter measures the frequency of input A

  • Decoder options: swapping A and B to reverse the counting direction, and counting only rising edges (rising_edge_only) instead of both

  • Position counter reset modes (enum ti_eqep_reset_mode, through ti_eqep_configure_qep()): reset on every index event, on the maximum position, on the first index event only, or on the unit time-out (frequency measurement)

  • Latch modes of the index, strobe and capture inputs (struct ti_eqep_qep_cfg): index latch on the rising edge, the falling edge or the index marker; strobe latch on the rising edge or direction dependent; capture latch on a counter read or on the unit time-out

  • Four alarm channels (enum ti_eqep_alarm_channel). An alarm fires once and passes the latched value as the ticks argument of the callback:

    Channel

    Event

    TI_EQEP_ALARM_CHAN_COMPARE (0)

    The position counter reaches the compare value. Relative alarms are added to or subtracted from the current position, depending on the counting direction. COUNTER_ALARM_CFG_ABSOLUTE and COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE are honored. The callback receives the compare value.

    TI_EQEP_ALARM_CHAN_STROBE (1)

    A strobe event. The callback receives the position latched on the strobe.

    TI_EQEP_ALARM_CHAN_INDEX (2)

    An index event. The callback receives the position latched on the index.

    TI_EQEP_ALARM_CHAN_TIMEOUT (3)

    The unit timer matches its period. The alarm ticks value is the period in module-clock cycles. The callback receives the position latched on the time-out.

  • Edge capture unit for low-speed measurement (ti_eqep_configure_capture()): a capture timer with a clock prescaler of 1 to 128 and a unit position event prescaler of 1 to 2048 quadrature periods. ti_eqep_get_latched_capture_values() returns the latched capture timer and capture period, optionally scaled by the prescaler.

  • Run-free operation under a debugger halt (the unit timer keeps running)

  • Module clock rate from the clock controller, reported by counter_get_freq()

  • Default pinctrl state applied at init

  • ti_eqep_configure_qep(), ti_eqep_configure_decoder(), ti_eqep_configure_capture() and ti_eqep_get_latched_capture_values() are system calls usable from user threads

  • AM13 variant only (CONFIG_COUNTER_TI_AM3352_EQEP_VARIANT_AM13):

    • source selection for the QEPA, QEPB and QEPI signals (ti,qepa-src, ti,qepb-src, ti,qepi-src): the Input X-BAR (default), a comparator output (CMPSS0 to CMPSS3) or a PWM X-BAR output (PWMXBAR1 to PWMXBAR8)

    • GPIO routing to an EQEP input through the Input X-BAR, with mux-states

    • peripheral power-up through the SYSCTL power enable register (ti,pwren)

Features NOT Supported

  • Hardware features the driver does not expose:

    • the watchdog timer that detects a stalled quadrature clock

    • position counter initialization on an index or strobe event (software only: 0 when counting up, the top value when counting down)

    • software-forced interrupts

  • Device power management is not implemented.

Usage

Enabling the Driver

CONFIG_COUNTER has to be set by the application:

CONFIG_COUNTER=y

CONFIG_COUNTER_TI_AM3352_EQEP defaults to on when an enabled ti,am3352-eqep node exists. It needs CONFIG_CLOCK_CONTROL and selects CONFIG_PINCTRL.

On the AM13 variant, CONFIG_COUNTER_TI_AM3352_EQEP_VARIANT_AM13 defaults to on. It selects CONFIG_MUX and CONFIG_SYSCON for the X-BAR routing and power enable.

Devicetree Configuration

On the AM13 variant, each EQEP input is hard-wired to a fixed Input X-BAR channel. Route a GPIO to that channel and names the entry:

&eqep0 {
        pinctrl-0 = <&gpio_pb11>;
        pinctrl-names = "default";

        /* PB11 (GPIO43) -> INPUTXBAR17 (ch 16) -> EQEP0A */
        mux-states = <&xbar1 16 AM13E2_XBAR_IN_STATE(43, 1)>;
        mux-state-names = "qepa";
};

A signal can instead come from an on-chip comparator or the PWM X-BAR, with no pinctrl or mux entry:

&eqep0 {
        ti,qepa-src = <TI_EQEP_SRC_CMPSS1>;
};

Measuring Position and Speed

Configure the decoder once, then read the counter. The decoder call also resets the position counter:

#include <zephyr/device.h>
#include <zephyr/drivers/counter.h>
#include <zephyr/drivers/counter/ti_am3352_eqep.h>
#include <zephyr/sys/printk.h>

static const struct device *const eqep = DEVICE_DT_GET(DT_NODELABEL(main_eqep0));

int main(void)
{
        struct ti_eqep_dec_cfg dec = {
                .source = TI_EQEP_SRC_QUADRATURE,
                .rising_edge_only = false,
                .swap_inputs = false,
        };
        uint32_t pos;

        if (!device_is_ready(eqep)) {
                return -ENODEV;
        }

        ti_eqep_configure_decoder(eqep, &dec);
        counter_start(eqep);

        counter_get_value(eqep, &pos);
        printk("position %u\n", pos);

        return 0;
}

Speed follows from two positions taken a known time apart. The index alarm reports the position at the encoder index pulse, which marks one turn:

static void index_cb(const struct device *dev, uint8_t chan, uint32_t ticks,
                     void *user_data)
{
        /* ticks is the position latched on the index event */
}

static int index_alarm_start(void)
{
        struct counter_alarm_cfg alarm = {
                .callback = index_cb,
        };

        return counter_set_channel_alarm(eqep, TI_EQEP_ALARM_CHAN_INDEX, &alarm);
}

The alarm fires once. Set it again in the callback to measure every turn.

For low speeds, enable the capture unit and read the latched values on a unit position event or the unit time-out:

struct ti_eqep_cap_cfg cap = {
        .enable = true,
        .clock_prescaler = TI_EQEP_CAP_CLK_DIV_64,
        .unit_position_prescaler = TI_EQEP_UNIT_POS_DIV_4,
};
uint32_t timer, period;

ti_eqep_configure_capture(eqep, &cap);
/* ... later, maybe in an ISR callback ... */
ti_eqep_get_latched_capture_values(eqep, &timer, &period, true);

The capture unit must be disabled before its prescaler changes; ti_eqep_configure_capture() does this itself.

MSPM0 Counter

Overview

The MSPM0 and MSPM33 General-Purpose Timer (GPTIMER) peripherals are exposed through Zephyr’s standard counter API (<zephyr/drivers/counter.h>). Each GPTIMER instance hosts a child devicetree node (ti,mspm0-timer-counter) that binds to this driver. The counter runs in up-counting mode and reloads to zero when it reaches the programmed top value. Compare-capture (CC) registers generate one-shot alarm interrupts when the counter reaches a programmed value.

Features Supported

The driver implements all mandatory counter API operations and the following optional operations:

  • Up-counting mode; counter_is_counting_up() always returns true

  • 16-bit or 32-bit counter resolution, selected per instance in devicetree

  • Up to 4 independent alarm channels backed by hardware CC registers (CC0–CC3); actual channel count is set per instance via the channels devicetree property

  • Top value and top-wrap callback (counter_set_top_value())

  • Alarm scheduling in relative and absolute modes (COUNTER_ALARM_CFG_ABSOLUTE)

  • Late alarm detection via COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE: when an absolute alarm deadline has already passed at call time, the driver pends the NVIC interrupt in software and fires the callback on the next interrupt dispatch instead of silently discarding the alarm

  • Reliable alarm cancellation: counter_cancel_channel_alarm() does not produce spurious callbacks after the alarm has fired or been cancelled

  • Guard period (counter_set_guard_period(), counter_get_guard_period())

  • counter_reset() — resets the counter to zero while it continues running

  • counter_set_value() — writes an arbitrary value to the counter while it is running

  • counter_get_freq() — returns the tick frequency after applying prescaler and clock divider

Features NOT Supported

The following Zephyr counter API features are not implemented:

  • 64-bit tick operations (CONFIG_COUNTER_64BITS_TICKS): counter_get_value_64(), counter_set_value_64(), counter_set_channel_alarm() with 64-bit ticks, counter_set_top_value() with 64-bit ticks

  • 64-bit frequency (counter_get_frequency_64(), CONFIG_COUNTER_64BITS_FREQ)

The following silicon capabilities have no corresponding Zephyr counter API and are therefore not accessible through this driver:

  • Input capture (edge timestamping via CC registers in capture mode)

  • QEI / quadrature encoder input (TIMG8 instances only; no Zephyr qdec driver is available for this platform)

  • Cross-trigger: hardware-to-hardware timer chains and ADC/DMA trigger output

  • Event fabric publish/subscribe (ZERO, LOAD, CC events to the MSPM0 event bus)

  • Repeat counter (trigger every N counts without CPU involvement)

Enabling the Driver

Enable the counter child node of the target GPTIMER instance in the board devicetree or an application overlay. CONFIG_COUNTER_MSPM0_TIMER is selected automatically when an enabled ti,mspm0-timer-counter node is present.

&counterg0 {
        status = "okay";
};

/ {
        aliases {
                counter = &counterg0;
        };
};

CONFIG_COUNTER=y

The counter alias is required by the standard counter alarm sample (samples/drivers/counter/alarm), which selects the device through DT_ALIAS(counter) when CONFIG_COUNTER_MSPM0_TIMER is set.

Important

TIMA instances (countera0_0, countera0_1 on MSPM33C; countera0 on MSPM0G) share the same GPTIMER hardware block with the PWM driver (ti,mspm0-timer-pwm). Enabling both child nodes on the same parent TIMA instance simultaneously is not supported.

Devicetree Properties

Counter node (compatible = "ti,mspm0-timer-counter")

Property

Description

resolution

Counter bit width: 16 or 32. Sets the hardware max_top_value to UINT16_MAX (65535) or UINT32_MAX (4294967295). Must match the capability of the parent GPTIMER instance.

channels

Number of alarm channels to expose (1–4). Each channel maps to one CC register (CC0–CC3). Hardware maximum is 4.

Parent timer node (compatible = "ti,mspm0-timer")

Property

Description

ti,clk-prescaler

TIMCLK prescaler. Range 0–255; the clock is divided by prescaler + 1 (÷1 to ÷256). Not available on TIMG12 instances, which have no hardware prescaler.

ti,clk-div

Post-prescaler clock divider. Accepted values: 1–8.

The counter tick frequency is:

f_counter = f_source / ((ti,clk-prescaler + 1) × ti,clk-div)

Usage

Free-Running Counter

With no top value set the counter wraps at the hardware maximum.

#include <zephyr/device.h>
#include <zephyr/drivers/counter.h>

const struct device *cnt = DEVICE_DT_GET(DT_ALIAS(counter));

if (!device_is_ready(cnt)) {
        return;
}

counter_start(cnt);

uint32_t ticks;
counter_get_value(cnt, &ticks);

Periodic Counter with Top Callback

static void period_cb(const struct device *dev, void *user_data) { }

struct counter_top_cfg top_cfg = {
        .ticks    = counter_us_to_ticks(cnt, 1000U), /* 1 ms */
        .callback = period_cb,
        .flags    = 0,
};

counter_set_top_value(cnt, &top_cfg);
counter_start(cnt);

Note

counter_set_top_value() returns -EBUSY if any alarm channel has an active callback. Cancel all pending alarms before changing the top value.

When COUNTER_TOP_CFG_DONT_RESET is set and the current counter value is already past the new top, the call returns -ETIME. Pass COUNTER_TOP_CFG_RESET_WHEN_LATE to force a counter reset in that case.

Alarm Scheduling

Each alarm is one-shot and is automatically disarmed after firing.

Relative alarm (fires ticks after the current counter value):

static void alarm_cb(const struct device *dev, uint8_t chan_id,
                     uint32_t ticks, void *user_data) { }

struct counter_alarm_cfg alarm_cfg = {
        .ticks    = counter_us_to_ticks(cnt, 500U), /* 500 µs */
        .callback = alarm_cb,
        .flags    = 0,
};

counter_set_channel_alarm(cnt, 0, &alarm_cfg);

Absolute alarm with late-expiry (uses cnt and alarm_cb from above):

struct counter_alarm_cfg alarm_cfg = {
        /* 1000 raw ticks at f_counter — use counter_us_to_ticks() for time-based values */
        .ticks    = 1000U,
        .callback = alarm_cb,
        .flags    = COUNTER_ALARM_CFG_ABSOLUTE |
                    COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE,
};

counter_set_channel_alarm(cnt, 0, &alarm_cfg);

Without COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE, a late absolute alarm returns -ETIME and the callback is never invoked.

Guard Period

The guard period prevents a relative alarm from being scheduled so close to the top wrap that the counter may have advanced past the target before the CC register write takes effect. counter_set_channel_alarm() returns -EINVAL for relative alarms whose tick value falls within the guard period.

counter_set_guard_period(cnt, 200U, COUNTER_GUARD_PERIOD_LATE_TO_SET);
