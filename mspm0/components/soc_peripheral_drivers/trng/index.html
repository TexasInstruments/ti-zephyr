TRNG

Important

The Peripheral will only work for MSPM0 series devices (lp_mspm0g3507, lp_mspm0g3519 and lp_mspm0l2228).

Overview

The True Random Number Generator (ti,mspm0-trng) is a hardware entropy source with built-in health tests. The driver implements Zephyr’s entropy API (<zephyr/drivers/entropy.h>) and is selected with CONFIG_ENTROPY_MSPM0_TRNG.

The hardware produces a 32-bit word at a time. The driver collects the words in the TRNG interrupt handler and stores them in a ring buffer, from which entropy_get_entropy() and entropy_get_entropy_isr() take their data.

Features Supported

  • Blocking entropy_get_entropy(): waits until the requested number of bytes is available. It is protected by a mutex, so several threads can use it.

  • entropy_get_entropy_isr(), usable from interrupt context. It returns the bytes already in the pool and, when ENTROPY_BUSYWAIT is passed in flags, waits for the remaining bytes.

  • Entropy pool filled in the background; its size is set with CONFIG_ENTROPY_MSPM0_TRNG_POOL_SIZE (default 256 bytes)

  • Configurable decimation rate of the generator (CONFIG_ENTROPY_MSPM0_TRNG_DECIMATION_RATE)

  • Start-up digital and analog self-tests run before the first sample is used

Features NOT Supported

  • DMA based data transfer. The CPU reads each word from the capture register.

Usage

The entropy API is meant for the random subsystem and for cryptographic services, not as a general random number function. Applications normally call sys_rand_get() and let the random subsystem use this driver.

Enabling the Driver

The LaunchPad board devicetrees already enable the node and choose it as zephyr,entropy. For another board, enable the node and choose it in the board devicetree (or an application overlay), and enable the entropy drivers in prj.conf. CONFIG_ENTROPY_MSPM0_TRNG is selected automatically once an enabled ti,mspm0-trng node is present.

/ {
        chosen {
                zephyr,entropy = &trng;
        };
};

&trng {
        status = "okay";
};

CONFIG_ENTROPY_GENERATOR=y

Devicetree Bindings

The node properties are described in ti,mspm0-trng devicetree binding.

Optional Kconfig

Symbol

Effect

CONFIG_ENTROPY_MSPM0_TRNG_POOL_SIZE

Size in bytes of the ring buffer that holds generated entropy. Default 256. Requests larger than the pool are served as the pool refills.

CONFIG_ENTROPY_MSPM0_TRNG_DECIMATION_RATE

Decimation rate of the generator, 1 to 8. Default 4, which is also the minimum the reference manual recommends. A higher value gives better entropy quality but makes each 32-bit word take longer to generate.

Reading Entropy

#include <zephyr/device.h>
#include <zephyr/drivers/entropy.h>

static const struct device *const entropy_dev =
        DEVICE_DT_GET(DT_CHOSEN(zephyr_entropy));

int main(void)
{
        uint8_t buf[16];

        if (!device_is_ready(entropy_dev)) {
                return -ENODEV;
        }

        /* blocks until all 16 bytes are available */
        return entropy_get_entropy(entropy_dev, buf, sizeof(buf));
}

From an interrupt handler, use entropy_get_entropy_isr(). It returns the number of bytes written to the buffer, which can be less than requested unless ENTROPY_BUSYWAIT is set:

int n = entropy_get_entropy_isr(entropy_dev, buf, sizeof(buf),
                                ENTROPY_BUSYWAIT);

The device is not ready if the driver cannot find a clock divider that brings the TRNG clock into the 9.5 MHz to 25 MHz range, which happens when MCLK is below 9.5 MHz. Initialization then fails with -EINVAL.

Tests

  • drivers.entropy (tests/drivers/entropy/api) - Reads random bytes from the zephyr,entropy device and checks that the buffer is filled and not overrun. It is built for lp_mspm0g3507, lp_mspm0g3519 and lp_mspm0l2228.
