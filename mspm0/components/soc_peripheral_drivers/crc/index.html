CRC

Overview

The CRC peripheral computes a checksum over a block of data in hardware. The driver implements Zephyr’s CRC driver API (<zephyr/drivers/crc.h>): a calculation is started with crc_begin(), fed with one or more calls to crc_update(), and completed with crc_finish().

There are two variants of the peripheral, each with its own devicetree compatible and Kconfig symbol:

Variant

Compatible

Kconfig

Boards

CRC

ti,mspm0-crc

CONFIG_CRC_TI_MSPM0

lp_mspm0g3507

CRC-P

ti,mspm0-crcp

CONFIG_CRC_TI_MSPM0_CRCP

lp_mspm0g3519, lp_mspm0l2228

CRC has a fixed set of polynomials (CRC16-CCITT and CRC32-IEEE). CRC-P has a programmable polynomial register, which lets it support more 16-bit and 32-bit algorithms.

Features Supported

  • Hardware CRC calculation through the Zephyr CRC API

  • Incremental calculation: the data can be passed in several crc_update() calls, from non-contiguous buffers

  • Configurable initial seed value

  • Independent control of input and output bit reversal (CRC_FLAG_REVERSE_INPUT and CRC_FLAG_REVERSE_OUTPUT can be set separately)

  • CRC: CRC16-CCITT and CRC32-IEEE

  • CRC-P: CRC16, CRC16-ANSI, CRC16-CCITT, CRC16-ITU-T, CRC32-C, CRC32-IEEE, CRC32-MPEG2 and CRC32-K/4.2

Features NOT Supported

  • DMA based data transfer. The CPU copies the data into the CRC input registers during crc_update().

  • Algorithms other than the ones listed above (for example CRC8). crc_begin() returns -EINVAL for them.

  • CRC: algorithms other than CRC16-CCITT and CRC32-IEEE, such as CRC32-C.

Usage

Enabling the Driver

Enable the CRC node in the board devicetree (or an application overlay) and the CRC subsystem in prj.conf. The driver is selected automatically once an enabled CRC node is present. The LaunchPad board devicetrees already enable the node and choose it as zephyr,crc, so no overlay is needed to run the sample.

/ {
        chosen {
                zephyr,crc = &crc;
        };
};

&crc {
        status = "okay";
};

CONFIG_CRC=y

Devicetree Bindings

The node properties are described in ti,mspm0-crc and ti,mspm0-crcp devicetree binding.

The MSPM0 SoC devicetrees describe the plain CRC (ti,mspm0-crc). A board whose device has a CRC-P peripheral selects the CRC-P driver by overriding the compatible, as lp_mspm0g3519 does:

&crc {
        compatible = "ti,mspm0-crcp";
        status = "okay";
};

Samples and Tests

Samples

  • CRC Sample

    • Computes one CRC over a fixed 8-byte buffer, logs the result and verifies it against the expected value.

    • The algorithm is selected with SAMPLE_CRC_VARIANT_* in the sample Kconfig; the default is CRC16-CCITT, and SAMPLE_CRC_VARIANT_CRC32_IEEE is also available.

Tests

  • drivers.crc (tests/drivers/crc) - Computes CRCs with the algorithms the driver supports (the others are skipped), including inputs split across several crc_update() calls, discontinuous buffers and access from more than one thread.
