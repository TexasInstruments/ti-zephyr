.. zephyr:code-sample:: eqep-position-speed
   :name: EQEP Position and Speed Measurement
   :relevant-api: counter_interface

   Measure simulated rotary encoder position and speed using the TI EQEP counter driver.

Overview
********

This sample demonstrates how to use the TI Enhanced Quadrature Encoder Pulse (EQEP)
counter driver to measure the position and rotational speed of a quadrature incremental
encoder.

It is fully self-contained: no physical encoder is required. A single TI EHRPWM
instance (``main_epwm0``), running in symmetric (up-down counting) mode, generates
*both* simulated quadrature phases from its two channels:

- Channel 0 (A) uses the driver's default action-qualifier behaviour: a 50%-duty output
  whose edges are tied to its own compare register, centered on the counter's
  zero-crossing.
- Channel 1 (B) is configured with the TI EHRPWM-specific
  :c:macro:`TI_EHRPWM_USE_AQ_SET_ZRO_PRD` flag (from
  :zephyr_file:`include/zephyr/drivers/pwm/ti_am3352_ehrpwm.h`), which ties its edges to
  the shared ZERO/PERIOD events instead of its own compare register.

Because both channels share the same symmetric time base, the result is two 50%-duty
square waves 90 degrees out of phase with each other - a quadrature pair generated
entirely from one peripheral's two channels, with no second PWM instance and no
dead-band hardware involved. A GPIO is pulsed once per simulated revolution to simulate
the index signal. These three signals must be jumper-wired back into the EQEP0 inputs
(see Wiring below).

The quadrature decoder is configured for 4x counting (both edges of both the A and B
channels). The position counter free-runs continuously rather than resetting each
revolution: it starts at the reverse-direction wrap boundary and only wraps after the
full 32-bit range, so consecutive index samples keep accumulating by
:kconfig:option:`CONFIG_APP_EQEP_LINES_PER_REV` * 4 counts per revolution instead of
restarting from zero.

The simulated A/B signals are generated by driving ``main_epwm0`` at
:kconfig:option:`CONFIG_APP_EPWM_OUTPUT_FREQ_HZ`, 50% duty, ``PWM_POLARITY_NORMAL`` on
both channels (channel 1 additionally sets ``TI_EHRPWM_USE_AQ_SET_ZRO_PRD`` as described
above).

The index pulse is derived from ``main_epwm0``'s period interrupt
(:kconfig:option:`CONFIG_PWM_EVENT`): the sample counts PWM periods and pulses the index
GPIO for one period every :kconfig:option:`CONFIG_APP_EQEP_LINES_PER_REV` periods, i.e.
once per simulated revolution.

Position and speed are reported by the EQEP's own index-event hardware alarm
(``TI_EQEP_ALARM_CHAN_INDEX``), not by a periodic timer: every time the index GPIO's
rising edge is latched by the decoder, the driver fires a callback with the position
counter's value at that exact instant, and the callback re-arms itself for the next
revolution (EQEP alarms are one-shot). With this A/B phase relationship the simulated
encoder counts down (counter-clockwise), so the reported position decreases every
revolution; the speed calculation subtracts in that order (previous minus current) so
the printed RPM comes out positive.

Requirements
************

This sample requires jumper wires between the simulated encoder signals and the EQEP0
inputs - no external encoder hardware is needed.

Wiring
======

On the :zephyr:board:`am62l_evm`, jumper the following pins:

- EHRPWM0_A  -> EQEP0_A
- EHRPWM0_B  -> EQEP0_B
- GPIO0_23   -> EQEP0_I

The EQEP0_S (strobe) input is unused by this sample and can be left unconnected.

Configuration
**************

- :kconfig:option:`CONFIG_APP_EQEP_LINES_PER_REV`: number of simulated encoder lines
  per mechanical revolution (default 1000).
- :kconfig:option:`CONFIG_APP_EQEP_UPDATE_INTERVAL_MS`: only changes the number printed
  in the startup banner below - position/speed are reported once per simulated
  revolution (driven by the EQEP index event), not on a fixed timer.
- :kconfig:option:`CONFIG_APP_EPWM_OUTPUT_FREQ_HZ`: simulated encoder electrical
  frequency, i.e. the EHRPWM output frequency (default 5000).

With the defaults above, expected speed = ``CONFIG_APP_EPWM_OUTPUT_FREQ_HZ * 60 /
CONFIG_APP_EQEP_LINES_PER_REV`` = 300 RPM, printed at startup for comparison against the
reported speed.
