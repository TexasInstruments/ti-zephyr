RTC

Overview

The MSPM0 RTC (ti,mspm0-rtc) is a hardware calendar peripheral clocked from a 32768 Hz source. The driver runs it in binary calendar mode and implements the standard Zephyr RTC API directly on the peripheral, with additional MSPM0-specific timer extensions. The RTC_x variant, found in the Low-Frequency Subsystem (LFSS), shares the same register layout.

Features Supported

  • Calendar time: set and get (year, month, day, hour, minute, second)

  • Two independent alarms with callbacks (CONFIG_RTC_ALARM)

  • Update callback fired once per second (CONFIG_RTC_UPDATE)

  • Frequency calibration in ppb (CONFIG_RTC_CALIBRATION)

  • Interval timer (RTCTEV): interrupt at every minute, hour, midnight, or noon (CONFIG_RTC_TI_MSPM0_INTERVAL_TIMER)

  • Prescaler timers RT0PS and RT1PS with configurable sub-second intervals (CONFIG_RTC_TI_MSPM0_PS_TIMER)

Features NOT Supported

  • BCD mode (driver uses binary calendar mode only)

  • DMA-based time-stamp capture

  • Tamper detection (time-stamp registers are present in hardware but not exposed through the Zephyr API)

Usage

The driver implements Zephyr’s standard RTC API (<zephyr/drivers/rtc.h>). MSPM0-specific extensions (interval timer and prescaler timers) are declared in <zephyr/drivers/rtc/rtc_ti_mspm0.h>.

Enabling the Driver

Enable the RTC node in the board devicetree (or an application overlay) and the RTC subsystem in prj.conf. CONFIG_RTC_TI_MSPM0 is selected automatically when an enabled ti,mspm0-rtc node is present.

&rtc0 {
        status = "okay";
        alarms-count = <2>;
};

CONFIG_RTC=y

Devicetree Bindings

The node properties are described in ti,mspm0-rtc devicetree binding.

Optional Kconfig

Symbol

Effect

CONFIG_RTC_ALARM

Enables alarm support. Requires the alarms-count devicetree property.

CONFIG_RTC_UPDATE

Enables update callback (rtc_update_set_callback()), fired once per second.

CONFIG_RTC_CALIBRATION

Enables frequency calibration in ppb (rtc_set_calibration() and rtc_get_calibration()).

CONFIG_RTC_TI_MSPM0_INTERVAL_TIMER

Enables the RTCTEV interval timer and the rtc_mspm0_set_interval_callback() extension API.

CONFIG_RTC_TI_MSPM0_PS_TIMER

Enables the RT0PS / RT1PS prescaler timers and the rtc_mspm0_set_ps_callback() extension API.

Extension API

Two non-standard callbacks are available when the respective Kconfig options are enabled.

Passing NULL as the callback disables the corresponding timer.

Interval Timer

Fires at a calendar boundary. The interval argument of rtc_mspm0_set_interval_callback() takes one of the following values:

Option

Interrupt fires

RTC_MSPM0_INTERVAL_MINUTE

when the minute changes

RTC_MSPM0_INTERVAL_HOUR

when the hour changes

RTC_MSPM0_INTERVAL_MIDNIGHT

every day at midnight (00:00)

RTC_MSPM0_INTERVAL_NOON

every day at noon (12:00)

 
#include <zephyr/drivers/rtc/rtc_ti_mspm0.h>

static void on_interval(const struct device *dev, void *user_data)
{
        /* called every minute */
}

rtc_mspm0_set_interval_callback(rtc_dev, RTC_MSPM0_INTERVAL_MINUTE,
                                on_interval, NULL);

Prescaler Timers

Fires at a sub-second rate. The RTC has two prescaler timers, selected with the timer argument of rtc_mspm0_set_ps_callback():

  • RTC_MSPM0_PS_TIMER_0 (RT0PS): microsecond to millisecond intervals

  • RTC_MSPM0_PS_TIMER_1 (RT1PS): millisecond to second intervals

The interval argument must come from the set that belongs to the selected timer.
