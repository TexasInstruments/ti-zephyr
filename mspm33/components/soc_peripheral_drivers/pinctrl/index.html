Pin Control

Overview

MSPM0, MSPM33, and AM13E devices route peripheral signals through an IOMUX block that contains one PINCM (Pin Configuration and Mux) register per physical pin. Writing a PINCM register selects which peripheral function appears on the pad and configures the pad’s electrical properties (pull, drive strength, open-drain, hysteresis, inversion).

The Zephyr pin control driver (pinctrl_mspm0) writes directly to the PINCM register array in the IOMUX peripheral. It is a helper used by other drivers; applications do not call the pin control API directly.

CONFIG_PINCTRL_MSPM0 is selected automatically when a driver that requires PINCTRL (GPIO, UART, SPI, I2C, PWM, CAN, …) is enabled.

Pin Encoding

Every pin configuration is described by a single 32-bit pinmux value built with the MSP_PINMUX macro:

/* From <zephyr/dt-bindings/pinctrl/mspm0-pinctrl.h> */
#define MSP_PINMUX(pincm, function) (((pincm - 1) << 0x10) | function)

pincm is the 1-based PINCM register index for the pin, taken from the device datasheet or pin tables. function selects which peripheral signal is routed to the pad:

Constant

Meaning

MSPM0_PIN_FUNCTION_ANALOG

Analog mode — disconnect the pin from all digital functions (writes 0 to PINCM, disabling the PC bit)

MSPM0_PIN_FUNCTION_GPIO

GPIO function (function select 1)

MSPM0_PIN_FUNCTION_2 … MSPM0_PIN_FUNCTION_15

Peripheral alternate functions 2–15. Which peripheral is mapped to each function number is pin-specific; look up the pin table in the device datasheet.

The driver sets bit 7 (PC, peripheral connect) automatically for all non-analog functions. A pinmux value with function = 0 clears the entire PINCM register to put the pad in a high-impedance analog state.

Note

The IOMUX PINCM register array starts at a different offset on MSPM0/MSPM33 vs. AM13E:

  • MSPM0 / MSPM33: PINCM[0] is at IOMUX_BASE + 0x4 (one reserved word before the first PINCM register).

  • AM13E: PINCM[0] is at IOMUX_BASE + 0x0.

The driver handles this automatically based on CONFIG_SOC_SERIES_AM13E.

All pre-defined nodes use the /omit-if-no-ref/ directive so unused pin configurations are dropped from the final DTB without any linker overhead.

Note

lp_mspm0g3507 and lp_mspm0l2228 pin definitions are maintained in the TI HAL module (modules/hal/ti/dts/). lp_mspm0g3519, lp_mspm33c321a, and lp_am13e230 use in-tree definitions under zephyr/dts/ti/. To inspect or modify pin assignments for a board, look in the location shown in the table above.

Enabling the Driver

CONFIG_PINCTRL_MSPM0 is auto-selected. The pinctrl node is enabled in the board devicetree:

&pinctrl {
        status = "okay";
};

This is already set in all supported board DTS files. No application-level change is needed.

Devicetree Properties

Each child node of &pinctrl represents one pin configuration state. The pinmux property is mandatory; all others are optional overrides.

Property

Description

pinmux

Required. MSP_PINMUX(pincm, function) — encodes the PINCM register index (1-based, from the datasheet) and the peripheral function number.

bias-disable

Disable internal pull resistor (tristate).

bias-pull-up

Enable internal pull-up resistor.

bias-pull-down

Enable internal pull-down resistor.

bias-high-impedance

Set pin to high-impedance mode.

drive-open-drain

Output driver is open-drain.

drive-open-source

Output driver is open-source.

drive-strength

Maximum output drive current in mA. 6 (default, standard I/O) or 20 (high-drive-capable I/O pins — HDIO — only).

input-enable

Enable the input buffer. Required for pins used as inputs or for I²C and other bidirectional open-drain signals.

ti,invert

Boolean. Logically inverts the digital input or output signal inside the IOMUX block.

ti,hysteresis

Boolean. Enables hysteresis on open-drain pins to improve noise immunity at the switching threshold.

Usage

Defining a Pin Configuration

Pin configurations live under &pinctrl in the board DTS or an application overlay. The DTSI already provides commonly used states; extend or override them as needed.

Note

PINCM indices and function numbers in the examples below are specific to MSPM0G3507 / MSPM0G3519. They will differ on other variants. Always look up the correct values in the device-specific pin table (datasheet appendix) or in the pre-built pinctrl DTSI for your board.

#include <zephyr/dt-bindings/pinctrl/mspm0-pinctrl.h>

&pinctrl {
        /* UART0 TX on PA10 (PINCM11, function 2) — MSPM0G3507/G3519 */
        uart0_tx_pa10: uart0_tx_pa10 {
                pinmux = <MSP_PINMUX(11, MSPM0_PIN_FUNCTION_2)>;
        };

        /* UART0 RX on PA11 (PINCM12, function 2) — input buffer required */
        uart0_rx_pa11: uart0_rx_pa11 {
                pinmux = <MSP_PINMUX(12, MSPM0_PIN_FUNCTION_2)>;
                input-enable;
        };

        /* I2C SDA on PB3 (PINCM16, function 3) — open-drain with pull-up */
        i2c1_sda_pb3: i2c1_sda_pb3 {
                pinmux = <MSP_PINMUX(16, MSPM0_PIN_FUNCTION_3)>;
                input-enable;
                drive-open-drain;
                bias-pull-up;
        };

        /* Analog input on PA23 — function ANALOG disconnects digital path */
        analog_pa23: analog_pa23 {
                pinmux = <MSP_PINMUX(24, MSPM0_PIN_FUNCTION_ANALOG)>;
        };
};

Applying a Pin Configuration to a Peripheral

Reference the pin nodes in the peripheral node’s pinctrl-0 property:

&uart0 {
        status = "okay";
        pinctrl-0 = <&uart0_tx_pa10 &uart0_rx_pa11>;
        pinctrl-names = "default";
};

The Zephyr pinctrl subsystem calls pinctrl_apply_state() during driver init, which invokes pinctrl_configure_pins() once per pin. Each call writes one PINCM register.

Optional Sleep State

Drivers with power management support can define a sleep state to reconfigure pins when the peripheral is suspended:

&uart0 {
        pinctrl-0 = <&uart0_tx_pa10 &uart0_rx_pa11>;
        pinctrl-1 = <&uart0_tx_pa10_sleep &uart0_rx_pa11_sleep>;
        pinctrl-names = "default", "sleep";
};

Where the _sleep variants typically use bias-pull-down or input-enable to prevent floating pins from drawing current.

Finding the PINCM Index for a Pin

The PINCM index for each physical pad is listed in the device-specific datasheet pin-multiplexing table (usually an appendix labelled “IOMUX” or “Pin Functions”). The index is 1-based in MSP_PINMUX and matches the PINCMx row in the table. The function number selects which row in the PINCMX.PF column corresponds to the desired peripheral signal.

The pre-built DTSI files already contain correct entries for all supported peripherals on each SoC variant. Consulting them is the easiest way to find valid combinations.
