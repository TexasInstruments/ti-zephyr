ti,tidss
########

.. sidebar:: Overview

   :Name: ``ti,tidss``
   :Vendor: :ref:`Texas Instruments <dt_vendor_ti>`
   :Used in: :zephyr:board-catalog:`List of boards <#compatibles=ti,tidss>` using
               this compatible
   :Driver: :zephyr_file:`drivers/display/display_tidss.c`

Description
***********



.. code-block:: none

   TI K3 family Display Sub-System (DSS) controller — generic binding.

   Supports any TI DSS variant regardless of how many VP/OVR/VID/VIDL
   blocks exist in hardware.  The DT node always describes exactly ONE
   pipeline triple that the driver shall use:

     DDR framebuffer  →  one video plane (VID or VIDL)
     →  one Overlay (OVR)  →  one Video Port (VP)
     →  OLDI TX or DPI pad

   The DSS register space must be split into four named MMIO regions:
     "common"  — top-level control, interrupt routing, MFLAG
     "vid"     — the video plane registers to use (vid, vidl1, vid2 …)
     "ovr"     — the overlay registers to use (ovr1, ovr2 …)
     "vp"      — the video port registers to use (vp1, vp2 …)

   These are LOGICAL names — the physical addresses in 'reg' select
   which actual hardware block is used.  This lets the same driver work
   on AM62L (1 VP, 1 VIDL), AM62P51/52 (2 VPs, 1 VID + 1 VIDL), or
   any future variant without driver changes.

   Panel timing must be provided via a child node named display-timings
   with compatible "zephyr,panel-timing".  Example::

     display-timings {
       compatible = "zephyr,panel-timing";
       clock-frequency  = <148500000>;
       hfront-porch     = <88>;
       hback-porch      = <148>;
       hsync-len        = <44>;
       vfront-porch     = <4>;
       vback-porch      = <36>;
       vsync-len        = <5>;
       hsync-active     = <1>;
       vsync-active     = <1>;
       de-active        = <1>;
       pixelclk-active  = <0>;
     };

   Supported SoC variants and their typical wiring
   ────────────────────────────────────────────────
   AM62L (single DSS):
     reg-names = "common", "vid", "ovr", "vp"
     physical  =  common(0x30200000), vidl1(0x30202000),
                  ovr1(0x30207000),   vp1(0x3020a000)
     ti,vp-index   = <0>   (VP1 = index 0)
     ti,vid-channel = <1>   (VIDL1)

   AM62P51 DSS0 — using VP2 (DPI):
     reg-names = "common", "vid", "ovr", "vp"
     physical  =  common(0x30200000), vidl1(0x30202000),
                  ovr2(0x30208000),   vp2(0x3020b000)
     ti,vp-index   = <1>   (VP2 = index 1)
     ti,vid-channel = <1>   (VIDL1)

Properties
**********

.. tabs::

   .. group-tab:: Node specific properties

      Properties not inherited from the base binding file.

      .. list-table::
         :widths: 1 1 4
         :header-rows: 1

         * - Name
           - Type
           - Details

         * - ``ti,vp-index``
           - ``int``
           - .. code-block:: none

                0-based index of the Video Port used by this pipeline.
                  0 = VP1 (first hardware VP)
                  1 = VP2 (second hardware VP)



             This property is **required**.

         * - ``ti,vid-channel``
           - ``int``
           - .. code-block:: none

                CHANNELIN value written to DSS_OVR_ATTRIBUTES[4:1].
                  0 = full VID plane connected to the overlay input
                  1 = VIDL1 (lite) plane connected to the overlay input
                Use 0 when the 'vid' region points to a full VID plane,
                use 1 when it points to a VIDL (lite) plane such as vidl1.



             This property is **required**.

             Legal values: ``0``, ``1``

         * - ``data-width``
           - ``int``
           - .. code-block:: none

                Output data bus width in bits.  Encoded into DSS_VP_CONTROL[10:8].
                Typical values are 18 (18-bit DPI) or 24 (24-bit DPI / OLDI JEIDA-24).



             This property is **required**.

             Legal values: ``12``, ``16``, ``18``, ``24``, ``30``, ``36``

         * - ``height``
           - ``int``
           - .. code-block:: none

                Height of the panel driven by the controller, with the units in pixels.



             This property is **required**.

         * - ``width``
           - ``int``
           - .. code-block:: none

                Width of the panel driven by the controller, with the units in pixels.



             This property is **required**.

         * - ``pinctrl-0``
           - ``phandles``
           - .. code-block:: none

                Pin configuration/s for the first state. Content is specific to the
                selected pin controller driver implementation.



         * - ``pinctrl-1``
           - ``phandles``
           - .. code-block:: none

                Pin configuration/s for the second state. See pinctrl-0.



         * - ``pinctrl-2``
           - ``phandles``
           - .. code-block:: none

                Pin configuration/s for the third state. See pinctrl-0.



         * - ``pinctrl-3``
           - ``phandles``
           - .. code-block:: none

                Pin configuration/s for the fourth state. See pinctrl-0.



         * - ``pinctrl-4``
           - ``phandles``
           - .. code-block:: none

                Pin configuration/s for the fifth state. See pinctrl-0.



         * - ``pinctrl-names``
           - ``string-array``
           - .. code-block:: none

                Names for the provided states. The number of names needs to match the
                number of states.

                Indicates the operational status of the hardware or other

                  - "disabled" means the resource is not operational and the system

         * - ``compatible``
           - ``string-array``
           - .. code-block:: none

                type of hardware or other resource this devicetree node
                represents. Each device driver checks for specific compatible
                property values to find the devicetree nodes that represent
                resources that the driver should manage.

                The recommended format is "vendor,device", The "vendor" part is
                an abbreviated name of the vendor. The "device" is usually from
                the datasheet.

                The compatible property can have multiple values, ordered from
                most- to least-specific. Having additional values is useful when the
                device is a specific instance of a more general family, to allow the
                system to match the most specific driver available.

                For details, see "2.3.1 compatible" in Devicetree Specification v0.4.

             See :ref:`dt-important-props` for more information.
