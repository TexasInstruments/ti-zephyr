IWDT — Independent Watchdog Timer

Watchdog Zephyr Documentation

Important

The IWDT lives inside the Low-Frequency Subsystem (LFSS). LFSS is present on MSPM0L (lp_mspm0l2228) and MSPM33 (lp_mspm33c321a) devices. MSPM0G3507 and MSPM0G3519 do not have LFSS and therefore do not have an IWDT.

Overview

The MSPM0L and MSPM33 Independent Watchdog Timer (IWDT) is exposed through Zephyr’s standard watchdog API (<zephyr/drivers/watchdog.h>). The driver implements all four mandatory operations: wdt_install_timeout(), wdt_setup(), wdt_feed(), and wdt_disable().

The IWDT lives inside the Low-Frequency Subsystem (LFSS) — the same always-on IP block that hosts the RTC. It is clocked by the LFOSC oscillator and continues running through STOP and STANDBY power modes. On timeout it generates a Power-On Reset (POR) of the entire SoC. There is no window constraint and no interrupt.

Features Supported

  • Free-running watchdog: feed any time before the timeout expires.

  • Eight selectable timeout periods (counter widths 26 to 225 LFOSC ticks), selected automatically from window.max.

  • Configurable clock divider (÷1 to ÷8) applied before the counter.

  • Pause when halted by debugger (WDT_OPT_PAUSE_HALTED_BY_DBG): counter halts when the CPU is stopped by a debug probe.

  • Only WDT_FLAG_RESET_SOC is accepted. The hardware always generates a POR; no other reset action is possible.

  • Single channel (channel 0) only.

  • After wdt_setup(), the IWDT register file is write-locked. A reset is required before the timeout period can be changed.

Features NOT Supported

  • Window minimum (window.min != 0 returns -EINVAL) — the IWDT has no closed-window hardware.

  • Callback — the IWDT generates a POR with no interrupt path. Passing a non-NULL callback to wdt_install_timeout() returns -ENOTSUP.

  • WDT_FLAG_RESET_CPU_CORE and WDT_FLAG_RESET_NONE — unsupported; only WDT_FLAG_RESET_SOC is accepted.

  • WDT_OPT_PAUSE_IN_SLEEP — the IWDT is in the always-on LFSS domain and continues counting through all sleep states.

  • Multi-stage timeouts (CONFIG_WDT_MULTISTAGE).

Important

The IWDT register key mechanism is a hardware safety feature: writes to WDTEN, WDTCTL, and WDTLOCK require the correct key value in the upper byte. Writing the wrong key to any of these registers immediately triggers a POR — it does not silently fail. This is a hardware invariant, not a driver behaviour.

After wdt_setup() the IWDT is locked against further configuration writes. Call wdt_disable() to unlock it for re-configuration.

Enabling the Driver

Enable the IWDT node in the board devicetree (or an application overlay) and the watchdog subsystem in prj.conf. CONFIG_WDT_MSPM0_IWDT is selected automatically when an enabled ti,mspm0-iwdt node is present.

&iwdt {
        status = "okay";
};

/ {
        aliases {
                watchdog0 = &iwdt;
        };
};

CONFIG_WATCHDOG=y

Devicetree Properties

Property

Description

clock-frequency

Frequency of the IWDT clock source (LFOSC) in Hz. Used by the driver to calculate the achievable timeout range and select the best PER and CLKDIV combination. Required.

Usage

#include <zephyr/device.h>
#include <zephyr/drivers/watchdog.h>

static const struct device *const wdt = DEVICE_DT_GET(DT_ALIAS(watchdog0));

struct wdt_timeout_cfg cfg = {
        .window = {
                .min = 0U,    /* IWDT has no window minimum */
                .max = 5000U, /* 5 s timeout */
        },
        .callback = NULL,         /* no callback — IWDT triggers POR */
        .flags    = WDT_FLAG_RESET_SOC,
};

int chan = wdt_install_timeout(wdt, &cfg);
wdt_setup(wdt, WDT_OPT_PAUSE_HALTED_BY_DBG);

while (1) {
        k_sleep(K_MSEC(1000));
        wdt_feed(wdt, chan);
}

Note

The IWDT counts from LFOSC independently of the main system clock. The actual timeout period is rounded up to the nearest hardware-supported value (2N / (clock-frequency / CLKDIV)). The effective period may be larger than window.max by up to one step of the period lookup table.

Samples

The standard in-tree watchdog sample (samples/drivers/watchdog) works with the IWDT. Point the watchdog0 alias at &iwdt in a board overlay or the board DTS:

/ {
        aliases {
                watchdog0 = &iwdt;
        };
};

&iwdt {
        status = "okay";
};

CONFIG_WATCHDOG=y

Note that the standard sample uses WDT_FLAG_RESET_SOC and sets window.min = 0, which are the only values accepted by the IWDT.

Tests

  • tests/drivers/watchdog/wdt_basic_api — exercises wdt_install_timeout(), wdt_setup(), wdt_feed(), and reset behaviour. A dedicated IWDT overlay boards/lp_mspm0l2228_iwdt.overlay is included for lp_mspm0l2228. To run on lp_mspm33c321a, provide an overlay pointing watchdog0 = &iwdt and enabling the iwdt node.
