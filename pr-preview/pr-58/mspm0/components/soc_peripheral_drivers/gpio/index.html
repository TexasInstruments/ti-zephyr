GPIO

Overview

The MSPM0, MSPM33, and AM13E GPIO peripheral (GPIOA, GPIOB, GPIOC) is exposed through Zephyr’s standard GPIO API (<zephyr/drivers/gpio.h>).

The driver calls the pin control subsystem (CONFIG_PINCTRL) internally to configure the IOMUX PINCM register for each GPIO pin at gpio_pin_configure() time. A pinmux phandle array in each GPIO node’s devicetree entry maps every pin number to its PINCM index and GPIO function. Applications do not need to call the pin control API directly for GPIO pins.

CONFIG_GPIO_MSPM0 is selected automatically when an enabled ti,mspm0-gpio node is present. It depends on and selects CONFIG_PINCTRL and CONFIG_SHARED_INTERRUPTS.

Note

Interrupt routing differs between device families:

  • MSPM0 (G / L series) — all GPIO ports share a single interrupt line (IRQ 1). The driver uses SHARED_INTERRUPTS to demux per-port callbacks from the shared vector.

Features Supported

  • Input and output pin direction configuration

  • Open-drain output mode

  • Pull-up and pull-down resistor configuration

  • Output initial value (GPIO_OUTPUT_INIT_HIGH, GPIO_OUTPUT_INIT_LOW)

  • Edge interrupts: rising edge (GPIO_INT_TRIG_HIGH), falling edge (GPIO_INT_TRIG_LOW), and both edges (GPIO_INT_TRIG_BOTH)

  • Per-pin interrupt callbacks (gpio_add_callback())

  • Wake-up from sleep (GPIO_INT_WAKEUP) — configured at init time; the PINCM wake-up enable bit is written once when the pin is configured and does not change at runtime

  • Drive strength: 6 mA (default) or 20 mA for HDIO-capable pins — set via the pinctrl drive-strength property, not via the runtime GPIO API

  • gpio_port_get_direction() — reads the current direction of each pin in a port (see known limitation below)

  • gpio_get_pending_int() — returns pending interrupt mask

Features NOT Supported

  • ``gpio_port_get_direction`` is unreliable in two cases (known driver limitation):

    1. Stale output state after reconfigure to input — the hardware DOE (Data Output Enable) register bit is not cleared when gpio_pin_configure() is called with GPIO_INPUT. If the pin was previously an output its DOE bit remains set, so gpio_port_get_direction() continues to report it as output after the reconfigure.

    2. ``GPIO_DISCONNECTED`` is indistinguishable from input — gpio_port_get_direction() uses only the DOE register: DOE=0 means output disabled, which is true for both input mode and disconnected mode. Pins configured with GPIO_DISCONNECTED are incorrectly reported as inputs. The hardware provides no separate “disconnected” state register.

    These two issues cause tests/drivers/gpio/gpio_get_direction to fail at runtime on all MSPM0/MSPM33 boards. The fix requires: (a) explicitly clearing the DOE bit in pin_configure when the mode is GPIO_INPUT, and (b) maintaining a software bitmap for disconnected pins since the hardware cannot distinguish disconnected from input.

  • Level-triggered interrupts (GPIO_INT_MODE_LEVEL) — the MSPM0 GPIO hardware is edge-triggered only. gpio_pin_interrupt_configure() returns -ENOTSUP when called with GPIO_INT_MODE_LEVEL.

  • Input glitch filter — the hardware has a 4-level debounce filter (none / 1 / 3 / 8 ULPCLK cycles) with no Zephyr GPIO API mapping.

  • Global fast wake — the hardware can switch the ULPCLK from 32 kHz to 32 MHz on the first GPIO interrupt to reduce IRQ latency; no Zephyr API for this.

  • Event publisher / subscriber — each port has three independent event channels (CPU_INT, GEN_EVENT0, GEN_EVENT1) that can publish GPIO edge events to the MSPM0 event fabric; no Zephyr GPIO API for this.

  • Runtime drive strength, hysteresis, and inversion changes — these are set only at pin configuration time via the pinctrl DT properties (drive-strength, ti,hysteresis, ti,invert); the GPIO pin_configure implementation hardcodes them to their reset values for any flags not expressed through the GPIO API.

Enabling the Driver

Enable the GPIO port nodes in the board devicetree. All supported boards already enable GPIOA and GPIOB.

&gpioa {
        status = "okay";
};

&gpiob {
        status = "okay";
};

CONFIG_GPIO=y

Devicetree Properties

GPIO node (compatible = "ti,mspm0-gpio")

Property

Description

pinmux

Phandle array of per-pin pinctrl child nodes, one phandle per pin index (0–31). Each phandle points to a node in &pinctrl whose own pinmux property contains the MSP_PINMUX(pincm, MSPM0_PIN_FUNCTION_GPIO) encoding. A NULL phandle (<0>) means the pin has no IOMUX mapping and cannot be used as GPIO. The SoC DTSI pre-populates this array; applications do not normally modify it.

reg

GPIO port base address. Set in the SoC DTSI.

interrupts

GPIO port interrupt line. All pins in the port share one interrupt vector; the ISR demuxes to per-pin callbacks.

gpio-controller

Required marker property (no value).

Usage

Configure and Read a GPIO Input

#include <zephyr/device.h>
#include <zephyr/drivers/gpio.h>

static const struct gpio_dt_spec btn =
        GPIO_DT_SPEC_GET(DT_ALIAS(sw0), gpios);

if (!gpio_is_ready_dt(&btn)) {
        return -ENODEV;
}

gpio_pin_configure_dt(&btn, GPIO_INPUT);

int val = gpio_pin_get_dt(&btn);

Configure and Drive a GPIO Output

static const struct gpio_dt_spec led =
        GPIO_DT_SPEC_GET(DT_ALIAS(led0), gpios);

gpio_pin_configure_dt(&led, GPIO_OUTPUT_INACTIVE);
gpio_pin_set_dt(&led, 1);   /* set high */
gpio_pin_toggle_dt(&led);   /* toggle */

Edge Interrupt with Callback

static struct gpio_callback btn_cb;

static void btn_handler(const struct device *dev, struct gpio_callback *cb,
                        gpio_port_pins_t pins)
{
        /* fired on rising or falling edge depending on configuration */
}

gpio_pin_configure_dt(&btn, GPIO_INPUT);
/* Register callback before enabling interrupts to avoid missing edges */
gpio_init_callback(&btn_cb, btn_handler, BIT(btn.pin));
gpio_add_callback(btn.port, &btn_cb);
gpio_pin_interrupt_configure_dt(&btn, GPIO_INT_EDGE_BOTH);

Important

Level-triggered interrupts (GPIO_INT_LEVEL_HIGH, GPIO_INT_LEVEL_LOW) are not supported. gpio_pin_interrupt_configure() returns -ENOTSUP for these modes.

Open-Drain Output

Passing GPIO_OPEN_DRAIN to gpio_pin_configure_dt() is sufficient; the driver sets the IOMUX open-drain bit automatically.

static const struct gpio_dt_spec led =
        GPIO_DT_SPEC_GET(DT_ALIAS(led0), gpios);

/* Driver programs the IOMUX open-drain bit from the GPIO_OPEN_DRAIN flag */
gpio_pin_configure_dt(&led, GPIO_OUTPUT_HIGH | GPIO_OPEN_DRAIN);

High Drive Strength

High-drive-capable I/O (HDIO) pins support up to 20 mA. Set drive-strength = <20> in the pin’s pinctrl node. This is a static configuration applied at boot; it cannot be changed at runtime through the GPIO API.

Samples

  • Blinky Sample — toggles the led0 alias using gpio_pin_toggle_dt(). Works on all supported boards without any overlay.

  • Button Sample — reads the sw0 alias and mirrors its state to led0. Uses gpio_pin_interrupt_configure() with GPIO_INT_EDGE_TO_ACTIVE. Works on all supported boards.

Tests

  • tests/drivers/gpio/gpio_basic_api — exercises pin configuration (input, output, open-drain, pull), port read/write/toggle, edge interrupt callbacks, and interrupt enable/disable. Passes on all five supported boards: lp_mspm0g3507, lp_mspm0g3519, lp_mspm0l2228, lp_mspm33c321a, and lp_am13e230.

  • tests/drivers/gpio/gpio_get_direction — known runtime failure on all MSPM0/MSPM33 boards. See the gpio_port_get_direction limitation in Features NOT Supported for the root cause.
