UNICOMM SPI

Zephyr SPI Documentation

Important

The UNICOMM SPI driver supports Texas Instruments microcontrollers am13e23019 and mspm33c321a.

  • Features Supported

  • Features NOT Supported

  • Usage

  • Samples and Tests

Features Supported

  • Controller (master) and peripheral (slave) mode operation

  • Motorola SPI frame format (3-wire and 4-wire)

  • TI frame format (SSI)

  • 8-bit data frame size

  • Configurable clock polarity (CPOL) and phase (CPHA) in Motorola mode

  • Internal loopback mode for testing

  • Interrupt-driven operation with 16-byte TX/RX FIFOs

  • Configurable TX/RX FIFO interrupt thresholds

  • Synchronous and asynchronous (callback-based) transfers

  • Runtime clock frequency configuration

  • GPIO chip-select management (controller mode)

Features NOT Supported

  • Data frame sizes other than 8-bit

  • Half-duplex mode with TI frame format

  • Hardware DMA support

  • Clock phase/polarity configuration in TI frame format

  • SPI clock frequencies above BUSCLK/2

Usage

The driver implements Zephyr’s standard SPI API (<zephyr/drivers/spi.h>). Applications use spi_transceive() for synchronous transfers and spi_transceive_async() for asynchronous transfers.

Enabling the Driver

Enable the UNICOMM SPI node in the board devicetree (or an application overlay) and the SPI subsystem in prj.conf. CONFIG_SPI_TI_UNICOMM is selected automatically once an enabled ti,unicomm-spi node is present.

&ucspi0 {
    status = "okay";
    pinctrl-0 = <&ucspi0_pins>;
    pinctrl-names = "default";
    cs-gpios = <&gpio0 10 GPIO_ACTIVE_LOW>;
};

CONFIG_SPI=y

FIFO Threshold Encoding

The TX and RX FIFO thresholds use hardware-defined encodings for a 16-entry FIFO.

TX Threshold (``tx-fifo-threshold``):

  • 0 = Interrupt when >= 12 entries free (<= 4 remain)

  • 1 = Interrupt when >= 8 entries free (<= 8 remain, half-empty)

  • 2 = Interrupt when >= 4 entries free (<= 12 remain)

  • 3 = Interrupt when >= 2 entries free (<= 14 remain)

  • 4 = Interrupt when >= 1 entry free (<= 15 remain, almost full) [default]

  • 5 = Interrupt when FIFO empty (all entries moved to shift register)

RX Threshold (``rx-fifo-threshold``):

  • 0 = Interrupt when >= 1 entry (not-empty, lowest latency) [default]

  • 1 = Interrupt when >= 4 entries

  • 2 = Interrupt when >= 8 entries (half-full)

  • 3 = Interrupt when >= 12 entries

  • 4 = Interrupt when >= 14 entries

  • 5 = Interrupt when FIFO full

SPI Modes and Configuration

Controller Mode (Master)

In controller mode, the UNICOMM SPI generates the serial clock and initiates transactions.

const struct device *spi_dev = DEVICE_DT_GET(DT_NODELABEL(ucspi0));
struct spi_config spi_cfg = {
    .frequency = 1000000,
    .operation = SPI_WORD_SET(8) | SPI_TRANSFER_MSB |
                 SPI_MODE_CPOL | SPI_MODE_CPHA,
    .slave = 0,
};

uint8_t tx_buf[] = {0x01, 0x02, 0x03};
uint8_t rx_buf[3];

const struct spi_buf tx_spi_buf = {.buf = tx_buf, .len = sizeof(tx_buf)};
const struct spi_buf rx_spi_buf = {.buf = rx_buf, .len = sizeof(rx_buf)};
const struct spi_buf_set tx = {.buffers = &tx_spi_buf, .count = 1};
const struct spi_buf_set rx = {.buffers = &rx_spi_buf, .count = 1};

int ret = spi_transceive(spi_dev, &spi_cfg, &tx, &rx);

Supported controller mode configurations:

  • Motorola 4-wire (standard SPI with separate CS)

  • Motorola 3-wire (half-duplex, bidirectional data line)

  • TI frame format (SSI, full-duplex only)

  • CPOL/CPHA modes 0, 1, 2, 3 (Motorola format only)

  • MSB-first or LSB-first bit ordering

  • Clock frequencies up to BUSCLK/2

Peripheral Mode (Slave)

In peripheral mode, the UNICOMM SPI responds to an external controller.

struct spi_config spi_cfg = {
    .frequency = 1000000,
    .operation = SPI_WORD_SET(8) | SPI_TRANSFER_MSB | SPI_OP_MODE_SLAVE,
    .slave = 0,  /* Not used in peripheral mode */
};

Supported peripheral mode configurations:

  • Motorola 4-wire and 3-wire formats

  • TI frame format

  • CPOL/CPHA configuration must match the controller

  • MSB-first or LSB-first bit ordering

Using TI Frame Format

struct spi_config spi_cfg = {
    .frequency = 1000000,
    .operation = SPI_WORD_SET(8) | SPI_TRANSFER_MSB | SPI_FRAME_FORMAT_TI,
    .slave = 0,
};

Asynchronous Transfers

void spi_callback(const struct device *dev, int result, void *userdata)
{
    if (result != 0) {
        LOG_ERR("SPI transfer failed: %d", result);
    }
}

int ret = spi_transceive_async(spi_dev, &spi_cfg, &tx, &rx, spi_callback, NULL);

Clock Configuration

The SPI clock is derived from BUSCLK using the formula:

\[f_{SPI} = \frac{BUSCLK}{2 \times (1 + SCR)}\]

Where SCR (Serial Clock Rate) is a 10-bit value (0-1023) configured at runtime based on the requested frequency. The driver automatically computes the appropriate SCR value during configuration.

Error Handling

The driver reports the following error conditions:

  • -EINVAL: Invalid configuration (unsupported mode, frequency too high, etc.)

  • -ENOTSUP: Unsupported feature (non-8-bit word size, half-duplex with TI format)

  • -EIO: RX FIFO overflow during transfer (data loss)

  • -EBUSY: Attempt to release while transfer in progress

  • -ENODEV: Clock device not ready

Interrupt Handling

The driver uses a single interrupt handler that dispatches to either controller or peripheral mode ISRs based on the current operating mode.

Controller Mode Interrupts:

  • RX FIFO threshold reached

  • RX FIFO full

  • TX FIFO threshold reached

  • TX FIFO empty

  • RX FIFO overflow (error)

  • SPI idle (transfer complete)

Peripheral Mode Interrupts:

  • RX FIFO threshold reached

  • RX FIFO full

  • TX FIFO threshold reached

  • SPI idle (controller deasserted CS)
